### Trappole degli strumenti, gia' pagate

- `get_task` vuole lo UUID INTERO. Un prefisso di 8 cifre da' "badly formed
  hexadecimal UUID string": si risolve prima con `list_tasks(q=...)` o con una
  `search` sul codice entita'.
- `list_tasks` prende `tag_id` e `state_id`, non `tag_ids` / `state` /
  `state_name`. Gli errori sono chiari ma costano un giro l'uno.
- `set_task_state` vuole `expected_version`, e il workflow **rifiuta
  todo -> verify**: si passa da `in_progress`. Stati:
  todo `181c039a-8536-43a0-9281-ce3fcba83f00`,
  in_progress `7cb9de9f-eb3b-4195-bbfd-e67a39debecf`,
  verify `4185cb12-3462-4dd7-92dd-870e1ecf1bee`,
  done `f44a26b1-609a-4f71-b8a8-79d4f990847c`
  (workflow `7ef2c2ec-9b0b-4125-b0f1-008e5255191b`).
- Il lavoro fatto si scrive come commento sul task (`add_comment`), non solo nel
  commit: e' li' che la prossima sessione lo trova.

## Come si chiude un task

`verify` quando e' fatto, `done` solo dopo una verifica AVVERSARIALE, perche'
`done` e' terminale. Avversariale vuol dire una MISURA, non una rilettura:

- un test nuovo va visto ROSSO senza il fix (togliendo il solo comportamento,
  non il campo o la firma, altrimenti misura la compilazione);
- un metodo ricostruito offline va confrontato con quello vero prima di
  fidarsene;
- vale anche contro la propria decisione appena presa. Il 2026-09-14 la regola
  "una nota prende uno slot" e' passata, e il test scritto per smentirla ha
  trovato il difetto speculare (una nota da cinque parti si mangiava la pagina).
  Scrivi cosa hai attaccato e cosa e' sopravvissuto, non solo la conclusione.

## Gate locali (== CI)

    export MYCELIUM_DATABASE_URL='postgresql+asyncpg://mycelium_app:mycelium_app@localhost:5433/mycelium' \
           MYCELIUM_DATABASE_URL_SYNC='postgresql+psycopg://mycelium:mycelium@localhost:5433/mycelium' \
           MYCELIUM_DB_APP_PASSWORD=mycelium_app
    uv run python -m pytest api/tests core/tests -q
    uv run mypy core/src api/src mcp/src worker/src sdi-inbound/src
    uv run ruff check . && uv run ruff format --check .
    uv run python scripts/gen_mcp_coverage.py --check
    cd web && pnpm check:api-types && pnpm exec vitest run && pnpm exec eslint . --no-cache

Note: il ruolo async DEVE essere `mycelium_app`, altrimenti i test girano da
superuser, le RLS non si applicano e sembra una falla di multi-tenancy che non
c'e'. La suite intera in locale supera l'ora e non conviene: un push del branch
NON fa scattare CI, si lancia a mano ed e' la risposta autorevole:

    git push origin v2.3 && gh workflow run ci.yml --ref v2.3
    gh run list --workflow=ci.yml --limit 1 --json databaseId,status

Se tocchi la PRIMA RIGA del docstring di un tool MCP, rigenera
`docs/mcp-coverage.md`. Se cambi uno schema dell'API, `cd web && pnpm gen:api`.

## Misurare qualcosa che il portatile non puo' dire

Un Job usa-e-getta sul pool di produzione, con lo script consegnato da una
ConfigMap generata dal repo, misura sul nodo vero senza ricostruire immagini e
senza toccare i pod in esercizio. Modello gia' scritto e funzionante:
`scripts/perf/reranker_pod_probe.py` piu'
`mycelium-production-k8s-deploy/reranker-probe-job.yaml` nel repo di deploy.
`kubectl` e' gia' sul contesto giusto. Chiedi prima di applicarlo: e' scrittura
sul cluster di produzione.
